# Security Policy

## Supported Versions

Security fixes are applied to the latest released version on the `main` branch.
Install the newest GitHub Release before reporting a suspected vulnerability.

## Reporting a Vulnerability

Do not open a public issue for a vulnerability involving authentication,
authorization, project files, PDF snapshots, credentials, or the editor proxy.
Use GitHub's private vulnerability reporting for this repository and include:

- the affected release or commit;
- reproduction steps and the expected security boundary; and
- impact, proof of concept, and any suggested remediation.

Do not include real access tokens, SSH keys, PDFs, account data, or server paths
in a report. Maintainers will acknowledge a valid report privately, assess its
impact, and coordinate disclosure after a fix is available.
